# 基础页面 · 组合与使用约定

> **范围：**新设计系统中由 `EzbScaffold`、`EzbAppBar` 及业务正文组合的基础页面。本文描述当前实现具备的能力；业务页面尚未确认的适配决策标“（待校准）”，不将已有组件视为全部设计已实现。
>
> **阅读顺序：**先读本文件，再读 [EzbScaffold](EzbScaffold.md) 与 [EzbAppBar](EzbAppBar.md)。颜色字段统一见 [AppColor](../Color/AppColor.md)，KYC 业务内容见 [KYC 通用约定](../KYC/00-通用约定.md)及各 Flow。

## §1 页面如何组成

1. 页面使用组合方式：业务页面提供一个 `EzbScaffold`，由容器承载导航栏、正文和底栏；业务页面无需继承组件类，也不在正文重复创建已由容器提供的导航栏。
2. 从上到下依次为系统状态栏区域、应用导航栏、业务正文和底部操作或导航区域。系统状态栏由设备绘制，不绘制设计示意中的时间、刘海、电量和信号；基础组件负责避让和配置系统栏颜色。
3. `EzbScaffold` 管理页面布局和栏位；`EzbAppBar` 管理顶部导航操作；`EzbIconButton` 承担默认玻璃返回按钮的图形、材质、触控和焦点反馈。各业务页面不复制这些内部实现。
4. 颜色从当前主题的 `EzbSemanticColors` 取得；根主题必须已挂载语义色扩展。业务页面以颜色用途取值，不将旧 `AppColor` 静态色直接替换到新组件中。
5. 历史 `HsgBasePage` 与 `HsgAppBar` 属于另一套容器。其正文边距、返回图标和标题样式不等于本组组件；不能仅因名称中含 BasePage 就认为已采用新导航栏。

## §2 从顶部到正文的布局职责

1. **状态栏下的导航操作：**标准导航栏的安全区、左右边距、返回按钮、文字操作以及显示条件统一按《EzbAppBar.md》§1–§5；页面只指定显示哪些操作、文案和业务回调。
2. **页面主标题与说明：**需要先区分“导航栏内文字”和“正文中的大标题”。内置文字的现有字号、行高、颜色见《EzbAppBar.md》§3；KYC 中 28px 大标题及其说明属于业务排版，不能直接用内置文字参数后宣称视觉已匹配。
3. **正文边距：**容器默认不添加正文外边距。普通 KYC 内容左右各16px时，由页面统一设置正文边距一次；导航栏已有自己的16px边距，不在其外层再套同一份页面边距。单张卡片自身的内边距与页面外边距分别计算。
4. **正文内容：**页面负责字段、卡片、标题、相邻间距和数据状态。基础容器不自动生成开户进度、校验提示、空态、加载态或业务错误页。
5. **底部操作：**固定操作通过 `bottomNavigationBar` 栏位承载，不放在长表单的末尾后假定其始终可见。底栏负责自身安全区；键盘避让和底部控件之间的具体关系见《EzbScaffold.md》§5。

## §3 固定与滚动的选择

1. **正文自行布局：**默认 `scrollable=false`。容器不创建滚动视图，适用于页面自行提供列表、滚动控件或含 `Expanded` 的布局；页面负责确保长内容可访问。
2. **使用容器滚动：**设置 `scrollable=true` 后，容器用一个纵向滚动区域承载正文；便捷参数提供的标题和副标题也移入同一滚动区域。返回和右侧操作仍在顶部，底栏仍在滚动区域之外。
3. 滚动布局的内置标题组与非空正文之间自动留16px。页面不得再为同一间距重复添加16px；需要不同业务标题样式时，标题由正文自己提供，是否保留组件自动间距需按实际组合核对。
4. 自定义 `appBar` 或 `hideAppBar=true` 时，不会再把便捷标题自动插入正文。页面仍需标题时自行提供，不能认为隐藏导航栏只隐藏按钮而保留自动标题。
5. 不在容器的无界纵向滚动内容中直接使用需要剩余高度的 `Expanded`；已有独立滚动控件的页面通常保持 `scrollable=false`，避免嵌套滚动职责不明。

## §4 返回、退出和资料保存

1. 默认返回按钮按路由能力显示，点击调用 `Navigator.maybePop`；显式 `onBack` 可覆盖按钮回调，自定义 `leading` 可完全替换前导控件。显示条件及优先级见《EzbAppBar.md》§2。
2. `onBack` 只负责可见按钮；基础组件没有替页面添加系统返回拦截。退出确认、系统返回、返回手势、Android返回键及数据保存必须由业务页或路由统一协调；默认 `maybePop` 会遵循路由现有的返回限制。
3. 草稿保存、跨页失效、重启恢复、申请退出和返回目标都由业务层定义。基础容器不会因收到返回回调而自动保存表单。
4. 需要右上角关闭时，可用自定义前导布局或自定义导航栏，但关闭图标位置、业务行为和系统返回必须有明确页面规则；不能把默认左侧返回按钮直接当成右侧关闭实现。

## §5 KYC 调用边界与待校准项

1. 标准页面应复用新导航栏；默认玻璃返回按钮的大小、箭头和材质按《EzbAppBar.md》§2，不在各 Flow 中分别实现按钮。
2. `EzbAppBar` 与 `EzbScaffold` 由其他维护方负责，本轮直接复用，不修改或扩展其实现。KYC 标准返回导航下方到正文标题顶缘的间距已校准为14px，由相关业务页面在正文顶部提供；仅返回按钮的标准44px高导航栏中，栏底与按钮点击区域底缘重合。间距从点击区域底缘测量，不从22px箭头图形底缘测量，不重复叠加正文顶部留白。顶部7px页面留白仍按《../KYC/00-通用约定.md》§2由业务页面提供，不写入基础组件。
3. 当前内置文字样式与 KYC 大标题及说明存在差异。KYC 页面在正文自建大标题和说明，标准导航栏只提供导航操作，不传入会重复显示文字的便捷标题；字号、颜色和标题下方间距仍按各页条款。14px属于页面顶部布局，不通过修改导航栏、内置标题组或容器默认值实现。
4. 基础组件现值与业务契约分别负责不同层级：本组文档说明调用能力，业务页定义目标内容。发现差异时保留明确待校准项，不以“组件默认”跳过业务规格，也不把页面估值写成组件已实现的默认值。

## §6 契约维护规则

1. 导航栏规格只维护在《EzbAppBar.md》，容器配置与优先级只维护在《EzbScaffold.md》；本文件说明整体关系，不复制完整控件规格。
2. 页面契约引用本库对应章节，并补充自己的标题、是否有返回/关闭、操作落点、退出确认、正文和底栏差异；不要求阅读外部设计或工程文件才能理解。
3. 行高沿用原始单位，每项只保留一个值，不换算；两种值都读到时保留第一个。本文引用到的排版值采用发布 token 的原始 px 值。
