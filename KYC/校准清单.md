# KYC 契约校准清单

> 本文件是**独立的草稿问题单**，不是已经生效的产品规则。四份 Flow 内以 Q 编号指向这里，避免同一问题写出多种答案。
>
> 可以按“Q06：采用……”“Flow 04，工作与收入页，Industry：改成……”回复。无需一次回答全部；每次确认后同步修改对应草稿，确认后的最终规则不保留讨论过程。

## 1. 范围、共用与视觉

### Q01 · 流程入口、顺序与范围

- **已知：**范围为 Flow 02–05；Flow 01、06、07 未作为整体纳入。
- **待校准：**开户入口、已登录但未开户用户入口、跨 Flow 返回、Back to start 的目标；是否纳入最小退出/续办入口。
- **待校准：**本文按页序整理的衔接是否正确，尤其国家资格、已有护照、PIN 与提交的先后。
- **涉及：**四个 Flow 的入口与出口。

### Q02 · 视觉参数与颜色校准

- **已确认：**`EzbScaffold`、`EzbAppBar` 本轮直接复用、不修改；标准返回按钮点击区域底缘到正文标题顶缘为14px，由 KYC 相关页面自行布局，正文标题不使用导航栏内置小标题替代。特殊结构按各页条款。

- **已知：**数值按正式 DTCG 发布包，结构状态按设计定稿；不复制截图猜值。
- **差异（待校准）：**部分设计按钮说明为高 52、圆角 26，而当前正式输入中 CTA 高为 56、圆角 28；部分行组件说明最小高 72，正式输入存在 64 的口径。
- **沿用既定口径：**正式 JSON 保持不变，当前按 CTA 高 56、控件圆角 28、行最小高 64；行组件的 72 差异为设计同步项，不重新打开已确认数值。
- **待校准：**是否有另行确认的新发布包；没有则沿用现行口径。缺失组件和变体需明确具体规格；有些组件说明保留旧图标字形命名，继续按已确认 Lucide 体系核对。
- **涉及：**全部页面；本稿没有自行发布新设计值，也不因说明冲突取消现行 token 的权威性。

### Q03 · 草稿、返回与恢复

- **已知：**设计写有自动保存、换手机不丢失、复核分组可修改。
- **待校准：**哪些步骤何时保存；返回、退出、重启和换设备分别恢复到哪里；保存时效与过期处理。
- **待校准：**改变居住国、重扫护照、切换就业类型或 TIN 状态后，哪些资料保留、清空或失效；编辑后是否直返复核。
- **涉及：**四个 Flow，尤其身份核验后资料和补件的恢复。

### Q04 · 未画出的通用状态

- **已知：**设计包含部分失败、缺失和禁用状态，尚未覆盖所有服务错误。
- **补充建议，待确认：**加载、空列表、无搜索结果、超时、重试、防重复点击、附件取消/失败、应用切后台和系统返回应有统一规则。
- **待校准：**提示位置、文案、按钮可用条件、重试落点及是否保留输入。
- **涉及：**需要请求、处理或上传的页面；不能推定模拟展示就是实际处理完成。

## 2. Flow 02

### Q05 · 国家推荐与资格判定

- **已知：**定位或手机区号可作推荐，用户选择的是永久居住国。
- **待校准：**来源优先级、首次是否请求定位、无推荐值时的画面、地区名称与编码、支持国家名单及判定时机。
- **待校准：**不支持国家页提到邮件通知，是否已有通知订阅依据及成功反馈。

### Q06 · 国家选择器

- **已知：**10c-b 的 Done 方案标为“备选”。
- **待校准：**采用哪个方案；是否有临时选择；Done/关闭/遮罩/系统返回各自是否确认或取消；搜索与无结果状态。

### Q07 · 巴林居民

- **已知：**“只建客户号、不开账户”，但出口存在待定批注。
- **待校准：**何时创建客户号、创建失败如何反馈、最终展示哪个出口、首页能力和帮助中心目标。
- **注意：**不能直接沿用普通不支持国家的处理，也不能默认为已经开户。

## 3. Flow 03

### Q08 · 护照、NFC、供应商与活体边界

- **已知：**一期需要芯片护照；活体匹配芯片照片；画面标注 Regtank，同时部分定制能力说明不一致。
- **待校准：**最终供应商与实际能力、相机/读取/活体画面中哪些可定制、关闭和失败回调、超时重试次数、返回位置。
- **待校准：**护照识别失败、非芯片证件、NFC 不可用或被关闭、活体失败和匹配失败的状态与出口。
- **待校准：**“对照政府记录”具体对应何种已确认能力，不因芯片读取自动宣称完成额外核查。

### Q09 · 身份字段、拒绝与重复账户

- **已知：**读出字段只读；缺失出生地必填；护照已有账户引导登录；疑似身份重复转人工。
- **待校准：**曾用名编辑性、出生地输入方式、重扫入口；有效期六个月如何计算；年龄上下限和即时拒绝原因。
- **待校准：**已有客户号与已有账户的区别、命中重复的判定步骤、引导登录前如何处理当前申请。

### Q10 · 换设备与通知

- **已知：**无 NFC 时提供换手机或留邮箱；读取失败提供重试或留邮箱。
- **待校准：**邮箱是否预填可改、格式与验证要求、通知订阅成功状态、去重；换设备恢复哪些资料及如何识别同一申请。

## 4. Flow 04

### Q11 · 就业与收入

- **已知：**三种就业类型及对应字段已画出。
- **差异（待校准）：**无业批注只问状态和收入来源，但画面包含年收入。
- **待校准：**无业是否保留年收入、初始类型、各项必填性、文本长度、行业/职业/国家/收入档位的完整选项与编辑形式。

### Q12 · 用途、资金来源与活动档位

- **已知：**前两组多选，活动量为档位。
- **待校准：**至少选几项、最多选几项、是否有默认值或额外选项；笔数和金额分别跨档时如何选档，10k/50k 等边界如何解释。

### Q13 · 地址与证明文件

- **已知：**邮编可选；本页一份地址证明；PDF/JPG/PNG、最大 10 MB；近三个月账单或租约。
- **待校准：**地址国家是否固定为居住国、地址字段规则、证明日期与地址匹配；文件页数、单位口径、压缩、预览、删除替换、失败与取消处理。
- **待校准：**后续补件是否统一沿用这些限制，还是每项材料分别限制；一项能否附多个文件。

### Q14 · 税务居民与 TIN

- **已知：**最多五组、首组不可删；无 TIN 可选三种原因。
- **待校准：**初始国家、组内必填、各国 TIN 格式、重复国家、删除确认和排序；五组时新增入口状态；其他原因的必填与长度。
- **待校准：**切换有/无 TIN 后隐藏值的处理及错误提示。

## 5. Flow 05

### Q15 · 复核与协议

- **已知：**复核四组可回改；四份文档可阅读但不强制；两项声明；记录版本和时间。
- **待校准：**摘要拼接、编辑回程、声明初始与保留状态；正式文档内容、链接和版本的关系；阅读加载失败、版本变化后是否重签。
- **注意：**设计 条款示例不是正式法律文本，本稿不擅自补成正式协议。

### Q16 · 交易 PIN

- **已知：**六位、两次确认、满位校验、两次不一致重设；只用于交易和卡。
- **待校准：**全部弱 PIN 算法和出生日期格式；错误后的清空、提示时长；已有 PIN 用户路径；PIN 保存与开户提交的先后和失败恢复。

### Q17 · 提交、审核与补件

- **已知：**存在成功、人工审核、补件、拒绝；全部材料上传后方可提交补件，再回审核。
- **待校准：**完整状态映射、进度展示、重复提交、超时与未知结果、状态刷新、通知与时效文案；各 CTA 落点。
- **待校准：**材料清单来源、每项必填与附件数量、驳回后的替换、提交中断恢复、Later 的返回目标；拒绝后是否允许重新申请。
- **注意：**一工作日、邮件已发、推送通知等承诺必须与真实业务一致。

### Q18 · 开户成功与首页承接

- **已知：**成功页有 Add money 和 Take a look around；首页只是未定稿示意，首笔入金要求来自本人同名他行账户。
- **待校准：**两个操作的目标、开户后最小首页范围、账户详情入口、首笔入金限制的提示与校验边界。
- **注意：**不因示意图存在导航、限额、账单和暂停支付入口，就把完整首页改造纳入本轮。

## 6. 校准完成标准

- 逐 Flow 确认页面和分支是否完整，排除供应商对比稿及备选误入。
- 所有影响页面结构、输入、状态或跳转的问题得到明确结论；可后补项注明适用边界。
- 按各页元素条款逐项校准；未确定值给出具体候选并就地标“（待校准）”，不再把外部设计或本清单当作缺失标注的替代。
- 已确认规则同步进入正文，删除对应待定表述；本清单保留的未决项不混作正式规则。
- 用户明确确认后，才将对应草稿整理为正式契约。契约库不记录开发计划、任务或执行进度。

## 7. 本轮 UI 逐项校准方式

- 色值与主题机制集中在《Color/AppColor.md》；KYC 页面只使用其中实际语义字段。
- 每页已按视觉顺序把尺寸、排版、颜色、间距、状态和点击结果写入对应元素条款；直接按页面和参数修改，如“国家选择器行高改为60，删除待校准”。
- 相机取景、NFC 插画、活体卡、PIN 键盘、通知成功反馈、上传与恢复行为中的预估项已在发生位置标“（待校准）”。
- 颜色和已发布基础值不是本轮估值；页面选中底、渐变方案、字段与旧画面差异仍需校准，不擅自改色板。
