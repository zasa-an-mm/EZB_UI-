> 用户已确认范围为可见FLOW T4、T4.1–T4.4。逐屏描述待校准；公共样式见本流程内的视觉规格与逐屏规则。列表视觉由本轮用户截图补充，后续各页完整属性尚待补读（待校准）。

## 本流程视觉规格（待校准项就地标注）


1. **页面与导航：**普通表单和详情复用基础页面，背景 `bgBase`；正文左右16px，宽窗口最大560px。返回、关闭、系统返回及返回手势遵循本屏业务返回规则；未明确落点时标“（待校准）”，不自动套用 KYC 清空规则。正文标题22px / w700 / 行高28px / `textPrimary`；标题相对导航点击区域的垂直距离（待校准）。有副说明时使用15px / w400 / 行高20px / `textSecondary`；标题与副说明、首个内容的间距未单独列明者（待校准）。
2. **表单：**标准输入底 `bgField`、圆角16px、左右16px、上下14px；标签13px / w400 / 行高18px / `textSecondary`，下2px为值17px / w500 / 行高23px / `textPrimary`，占位 `textTertiary`。文字自撑高，最小高度（待校准）。聚焦2px `borderFocus`，标签 `textBrand`；错误辅助文案13px / w400 / 行高18px / `feedbackError`，与字段间距、错误背景及边框转换（待校准）。禁用 `bgDisabled`／`textDisabled`；只读保留正常文字颜色，不伪装成不可辨认的禁用态。未取得字段间距时逐屏标注，不默认照搬 KYC。
3. **金额：**当前开发采用正式34px / w700 / 行高40px、圆角16px；输入左右16px、上下14px，符号与金额间4px；符号 `textSecondary`，金额 `textPrimary`。设计曾为圆角14px，最终视觉匹配（待校准），不新增正式 token。余额／额度说明13px / w400 / 行高18px / `textSecondary`，距金额8px。
4. **主次操作：**主按钮最小高56px、圆角28px、文字17px / w600 / 行高23px；正常 `brandPrimary`／`textOnBrand`，禁用 `bgDisabled`／`textDisabled`。文字换行可增高，处理中阻止重复触发并播报状态；按下态复用正式按钮状态。次操作的具体表面、危险按钮颜色和相邻间距未明确者（待校准），不猜值。固定底部操作区与正文共用内容列，底部消费实时安全区；区域上下内边距（待校准）。
5. **半框：**背景表面语义、顶部圆角、标题到内容间距（待校准）；标题22px / w700 / 行高28px / `textPrimary`。宽窗口最大560px，矮窗口限高90%，内容内部滚动；操作和固定 Other 不被滚动区或系统栏遮挡。外点、下滑、系统返回是否关闭依各屏规则，未明确者（待校准）。
6. **行、详情与空态：**标准行最小高72px，上下8px；左40px图形容器、图形20px，与文字间12px。主文17px / w500 / 行高23px / `textPrimary`，副文15px / w400 / 行高20px / `textSecondary`，尾随箭头20px；头像字母15px / w600 / 行高20px。详情字段标签和值的布局、分隔线及行距未取得者（待校准），不能仅因复用组件省略差异。空态标题22px / w700 / 行高28px，说明15px / w400 / 行高20px；插画、对齐和间距依各屏，缺项（待校准）。
7. **适配与可访问性：**同名语义 token 分别映射明暗主题。支持100%／200%字号，长文自然换行；图标装饰不重复朗读，交互图标须有可读名称，独立点击区至少44px。310px窗口可用，安全区和键盘分别避让，底部导航、PIN删除键和主要操作不得被系统栏遮挡。


## §1 T4.1 列表与搜索

1. **页面与标题：**返回来源页，标题 Payees；导航右 plus 的资源／尺寸／颜色（待校准），点击区至少44px。正文搜索、筛选、Favourites、Other payees 依次排列；内容列、安全区与本流程视觉规格一致。搜索非必填，不自动弹键盘。
2. **搜索与筛选：**搜索使用标准字段，标签 Search、占位 Name, account or email；筛选 All／EZB／Other banks 单选，芯片尺寸、选中背景、项间距和与搜索间距（待校准）。输入不作账号格式校验；正式昵称／混合字符匹配规则（待校准）。
3. **联系人与空态：**行用本流程视觉规格，星标独立44px命中区，实心／空心图标资源与颜色（待校准）。分组标题字号／行高／上下间距（待校准）；无星标、全星标、全空和搜索无结果是不同状态，不合并。无结果完整标题、插画与按钮间距（待校准）。
4. **状态同步与离开：**搜索不改底层联系人，切筛选保留查询；具体恢复规则（待校准）。星标更新首页／详情／列表，失败反馈和回滚（待校准）；同一人不复制。

**逐元素与状态细则：**

1. 页面标题Payees，左返回，右plus为Add a payee；搜索标签Search，占位Name, account or email。筛选All／EZB／Other banks，单选；选择项按品牌底色与对应前景token，未选为表面色；准确Chip尺寸依正式组件，截图不估尺寸。
2. Favourites在前，不设数量上限；Other payees在后。同一人不重复出现。其余按最近往来排序，设计说明转出、转入、添加都算；T1按最近转出／添加且最多3条，两者是否应完全一致（待校准）。
3. 点击行进入详情；星标图标为独立动作，不触发整行导航。星标增删即时更新分组；失败回滚、并发和组内排序（待校准），不能先展示成功再吞错。
4. 输入即时过滤、不校验查询串格式；字母匹配姓名及行内邮箱，数字匹配行内账号及海外IBAN／账号，有结果显示N results，无结果显示空态。昵称、混合字母数字、大小写及模糊规则在注释间不完整，见（待校准）事项。
5. 无星标仍显示Favourites空卡：No favourites yet／Tap the star on a payee to keep them here.；全为星标时Other payees空卡：No other payees，用户截图副文Everyone you’ve saved is in your favourites.。
6. 无联系人：搜索禁用、筛选隐藏；右上plus与正文Add a payee主操作均可用。搜索无结果保留查询与筛选，正文再放同款新增主操作；具体空态标题、插画、图标和布局待补读。
7. 来源按后续明确注释：转出成功自动保存、手动添加；转入不自动保存。封面“收过款的人自动存下”为冲突旧文案，不可静默当最终规则。

## §4 T4.4-a 详情、昵称与星标

1. **详情结构：**返回联系人列表；对象身份、行内／海外银行资料、昵称编辑、Favourite、Send money、最近往来和删除操作。准确字段顺序、分组、行距、银行图形及完整／掩码账号展示（待校准）。标准标签和值按本流程视觉规格，不将只读画成禁用。
2. **昵称半框：**标准选填输入，保存后更新详情、首页和列表；标题、占位、按钮文案、清空后的回退名、长度字符及关闭行为（待校准）。取消不应静默提交未确认编辑；失败提示和重试（待校准）。
3. **星标与转账：**开关即时同步，开关尺寸、选中／未选中表面（待校准）。Send money 依类型进入对应金额，仍核对账户有效性／变化和付款资格。
4. **最近往来：**最多3条、最新在前；交易金额、方向、时间和状态来自历史事实，行样式、空态和 See all 间距（待校准）。See all 保留本联系人筛选；全历史页的标题、排序、加载／空／错误状态（待校准）。

**逐元素与状态细则：**

- 分行内／SWIFT详情，展示银行信息、昵称、星标及最近往来；Send money分别进入T2-01／T3-03并检查联系人有效性。
- 银行信息不能修改，要改删后重加；昵称可编辑。昵称半框保存后回详情；长度、字符、空昵称回退名、取消保留与错误态（待校准），不把“随便改”当无约束校验。
- Favourite开关即时生效；详情与列表及T1展示同步，同一对象不复制。完整账号是否可显示／复制、脱敏方式及截图级别按最终字段校准，不由用户截图的尾号推断全部字段均脱敏。
- 最近往来最多3条，转出和转入均算、最新在前；See all进入此联系人全部交易，不跳到无筛选全流水。交易详情及联系人历史复用既有能力，缺失的新UI属性（待校准）。
